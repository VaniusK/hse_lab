# Задание 1. Холодный и тёплые прогоны Colibri

Скрипт поднимает Colibri с уже скачанной моделью, отправляет три отдельных запроса и сохраняет результаты в Phoenix и CSV. Compose запускает Phoenix, а скрипт и движок Colibri работают внутри контейнера бенчмарка.

## Запуск

Проверь три промпта в `prompts/01.txt`, `prompts/02.txt` и `prompts/03.txt`. Они должны быть примерно одной длины. Затем скопируй `.env.example` в `.env` и укажи каталог модели в `MODEL_DIR`.

В Windows с Docker Desktop укажи путь вида `C:/Users/имя/colibri-models/qwen36-35b`. В WSL с включённой Docker-интеграцией укажи путь вида `/mnt/c/Users/имя/colibri-models/qwen36-35b`. Веса монтируются для чтения. Образ использует Colibri 2.2.0 на Linux x86-64 в режиме CPU. Если та же модель запущена в Windows, останови её перед серией, чтобы освободить ресурсы.

Из каталога проекта выполни:

```sh
docker compose up -d phoenix
docker compose run --rm --build benchmark
```

Открой `http://localhost:6006` и выбери проект `hse-colibri`. Скрипт выводит идентификатор трейса и путь к CSV в `output/`. Промпты монтируются из каталога проекта, поэтому после их правки достаточно повторно запустить бенчмарк.

## Как читать замеры

- Спан `colibri.startup` измеряет время от запуска нового процесса Colibri до готовности его API. Подготовка Docker-образа проходит до замера. Файловый кэш ОС может сохраняться между сериями.
- `cold` — первый запрос после готовности нового процесса. `warm-1` и `warm-2` идут в тот же процесс без истории сообщений. У `cold` есть дополнительное поле `total_with_startup_seconds`, равное сумме загрузки и времени запроса.
- `ttft` — время от отправки запроса до получения первого непустого текстового фрагмента. Это приближение к TTFT на стороне клиента. `run_seconds` — время от отправки до окончания потока.
- `input_tokens` и `output_tokens` приходят из блока `usage` того же ответа. `output_speed` оценивается по числу выходных токенов после первого и интервалу между первым и последним текстовыми фрагментами. Если поток пришёл одним фрагментом или счётчика нет, поле скорости остаётся пустым.
- В CSV сохраняются тексты запросов и ответов, причина завершения и идентификатор трейса. Для таблицы отчёта возьми поля из одной строки на каждый прогон. При сравнении задержек учитывай объём ответов и показывай время загрузки отдельно.

Phoenix хранит трейсы в томе `phoenix-data`. Команда `docker compose down` останавливает стенд с сохранением трейсов.
